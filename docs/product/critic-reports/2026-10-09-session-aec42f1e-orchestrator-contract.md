## Defects not mentioned by the orchestrator

1. **The room check fails open on an empty list (security, high).** `verdict([])` returns "team". Treat zero conference records or zero non-self participants as mixed, and add a test for it. Paginate both list calls.
2. **The brain's reach is wider than "the repo" (security).** `Read`, `Grep` and `Glob` are allowed with no path scope under `dontAsk`, so the brain can read anything `snoop` can. That includes world- or staff-readable files in `/tmp` (the plans themselves write `/tmp/bundle-check` with a copy of the registry, plus `/tmp/claude-help.txt`), `/Users/Shared`, `/opt/homebrew`, and other users' homes. Scope the tools to the knowledge dir, or give `snoop` its own primary group.
3. **The API key leaks into child processes (security).** `os.environ["ANTHROPIC_API_KEY"] = ...` in `brain_main` is likely inherited by the CLI's stdio MCP children: Serena, its language servers, and registry-mcp's `node_modules`. `snoop` also has unrestricted OS network egress. Doctor check 4 only asks the model to print the key. Pass the key only to the CLI, or strip it from the MCP server env.
4. **`--dev` drops the wall entirely (security).** It runs as the host on the host's login with the sandbox off, so Read covers `~/.config/snoop/secrets`, `~/.ssh` and so on. The gate catches only key-shaped strings. Refuse `--dev` while a meeting room is live, or restrict it to a fixture repo.
5. **Root setup in `/Users/Shared` (security).** See 10(b). Refuse to run if `{shared}` already exists and is not a real directory owned by the owner. Use `chown -hR`, or do no recursion at all on a fresh `mktemp`-style directory.
6. **The git Bash allowlist can write (security, low).** `git diff --output=<file>` and `git branch <name>` / `-D` are writes. OS permissions limit them to `snoop`'s home and `/tmp`, but the "read-only tools" claim is not literally true.
7. **P3 tested the wrong configuration.** See claim 4(f). Production uses `setting_sources=[]` with no `--settings` file and the bundled 2.1.286 CLI. Re-run the controls through the SDK as `snoop`, and make each negative check assert a permission-denial event and the absence of errors.
8. **The Serena pin cannot be satisfied from PyPI** (claim 9). The spec's mitigation in §5.3.1 is not achievable as written. The startup `assert_tools` plus the CLI allowlist are the real controls.
9. **Estimates disagree across documents** ("~1 week" in D33 and Plan 0 versus "1–2 weeks" told to Brett), and Plans 1–3 run ahead of the unrun Meet probes P1 and P2. The P1 failure mode feeds directly into defect 1.
10. **P1 is an open question.** If the host's token is not the organizer's, the plan's assumption that the call "fails closed" depends on the API returning an error rather than an empty list. That is unproven.

Overall verdict: The orchestrator's factual research on third-party systems is mostly accurate: Attendee, the Meet Media API, the macOS permissions, registry-mcp and Serena's settings all check out. But several load-bearing claims about its own work are overstated or wrong. The "CLI has no `--max-turns`" finding is false: the flag is hidden, and the SDK passes it to the CLI. The sandbox probe's negative control validates only one of its three checks, and the probe tested a different CLI version and configuration from production. The $9.75 cost record does not exist in Agent-C's `cost.json`. The quoted support-article language is no longer on the page, and the SDK-credit status changed on Oct 7. On security, the plans have one high-severity fail-open (an empty participant list is treated as an all-team room and Snoop speaks). They also have unresolved hardening gaps: root recursive chown/chmod in `/Users/Shared`, sudo likely keeping HOME, unscoped Read, the API key likely inherited by MCP children, and a `--dev` mode with no wall. These are not mentioned to Brett, and Plans 1–2 should not be built as written until they are fixed. Critic side effect, disclosed: while testing claim 3, one live `claude -p hi --max-turns 0` call ran from the yo-snoop directory. It cost $0.44 api-equivalent and was recorded by the session hook in `yo-snoop/docs/product/cost.json` as session 8ff5bfb3. No other writes were made.
